# RTL Live: bugs and corrections

Collected during use. Fix all at the end, together with docs/ACCURACY.md.

## Bugs found

1. **Module name overflows its box.** Typing `module top_module(` alone shows a box with a huge, clipped title ("top_modul"). The box should grow to fit its label, and Fit should not zoom a tiny diagram above 100%.
2. **Badge and drawing disagree.** After deleting most of a synthesized file, the badge says "Stale, fix the error to resynthesize" but the last good diagram is replaced by a structural box. Pick one behavior: keep the last good diagram with "Stale", or show the live structural view with an "Editing" badge.
3. **Vague error messages.** Location is right for mid-line errors (`7458.v:2:29` for `input p1a, p1b, p1c p1d p1e, p1f` was exactly where the missing comma is), but wrong for errors at the end of the file (`1:1` when `);` and `endmodule` were missing). The message is always just "syntax error". It should say what is missing: `missing ','`, `missing ';'`, `missing ');' to close the port list`, `missing endmodule`. Also: while the code has an error, parsing recovery silently drops ports (p1c and p1e vanished from the structural view); show dropped items greyed out instead of hiding them.
4. **Sidebar stuck on the previous file after sleep.** After the Mac slept overnight, switching to `arith_compare.v` kept showing the 7458 diagram ("Synthesized, cached"). The output log had no new lines since the night before. Developer: Reload Window fixed it.
9. **Unsaved new files are ignored.** A new `Untitled-1` file in Plain Text mode containing Verilog shows "Open a Verilog file (.v or .sv)". Either render untitled files that look like Verilog, or show a hint with a one-click "Set language to Verilog" action.
10. **Structural view scatters ports in a grid.** With a syntax error, the structural module box places ports in a 2-column grid (p1a, p1b / p1c, p1y / p2a, p2b / p2y). Inputs should be on the left edge and outputs on the right edge, in declaration order, at normal text size.
11. **Webview fails to load in a newly opened window.** Opening a second VS Code window with `open -a` left the sidebar blank with "Error loading webview provided by 'vejaysuriyaa.rtl-live': Could not register service worker: InvalidStateError: The document is in an invalid state." This is a VS Code webview issue, but the extension should detect a failed load and retry, or show a "Reload to fix" message instead of a blank panel. Likely root cause: two VS Code versions (1.106.3 real app and the 1.143.0 test copy) sharing one user profile, which is a known trigger for this error. Fix the environment (bug 12) and update the real VS Code so only one version is in use.
12. **Test harness shares the real VS Code profile.** Integration tests ran with `~/.vscode/extensions` and the real profile, which let an autosave extension edit fixtures during a test run and leaves two VS Code versions using the same profile. Tests must always use an isolated `--user-data-dir` and `--extensions-dir` in a temp folder.
13. **(v0.2.0) A port still vanishes during error recovery.** With `input p1a, p1b, p1c p1d p1e, p1f,` (two missing commas), the structural view shows p1a, p1b, p1d, p1e (ghosted) and p1f, but `p1c` is missing entirely, and the `w1 = p1a & p1b & p1c` cloud only connects p1a and p1b. Every identifier in a broken port list should appear, ghosted if uncertain.
14. **(v0.2.0) Wires too crowded near input fan-out.** In vectorgates, the `a[2:0]` and `b[2:0]` trunks run a few pixels apart as they fan out to the OR, logical OR and NOT gates, so it is hard to tell which wire feeds which gate, and crossings look like junctions. Increase edge-to-edge spacing and the gap between the port column and the first gate layer (ELK `spacing.edgeEdge`, `layered.spacing.edgeEdgeBetweenLayers`, `layered.spacing.edgeNodeBetweenLayers`), and make junction dots clearly larger than wire width.
15. **(v0.2.0) Join labels cramped.** The `[5:3]` and `[2:0]` labels on the join into `out_not` are tiny and overlap each other and a marker dot. Give each join input its own label space.
16. **(v0.2.0) Unexplained dashed yellow segment.** The wire between the join and `out_not[5:0]` is drawn dashed yellow. If this means something (warning, highlight), it needs a tooltip or legend; if not, it should be a normal bus wire.
17. **(v0.2.0) Logical OR glyph is unclear for beginners.** The logical OR is drawn as an OR gate with two small vertical lines (`||`) inside. A learner cannot tell what the lines mean. Better options: draw the logical OR the way it really works (each input bus goes through a small "any bit set?" reduce box first, then a normal 1-bit OR), or keep the symbol but add a clear label and a hover tooltip: "Logical OR: 1 if any bit of a or any bit of b is 1. Output is 1 bit." Same treatment for logical AND and logical NOT.
18. **Beginner-friendly explanations for every symbol.** Every visual element should explain itself on hover, in one plain sentence: bus slash with width ("3 separate wires drawn as one line"), join bar ("glues buses together: top input becomes bits [5:3]"), rippers and slice labels, junction dots versus plain crossings ("dot = connected, no dot = just crossing"), inversion bubbles, logical versus bitwise gates, mux input labels, flop clock triangle, latch warning, dashed or colored wires. Add a small "Legend" button in the toolbar that shows all symbols with one-line meanings. Spacing, labels and tooltips should all be judged against "would a first-week Verilog learner understand this?"
19. **(v0.3.0) Crowded fan-out hub.** In vectorgates, the junction dots next to `b[2:0]` sit within a few pixels of each other, and a plain crossing sits right beside a junction dot, so the hub reads as one blob. Junction dots must be at least 20 px apart and a plain crossing at least 16 px from any junction dot; both are L3 checks on every fixture in every view.
20. **(v0.3.0) Legend labels wrong size and clipped.** In the Legend panel the split bar sample draws `[5:3]` and `[2:0]` far larger than the diagram does and they overlap the title and description; the join bar sample label is clipped to `:0]`. Legend samples must use the same label size as the diagram, fit inside their sample area, and never overlap the text column.
21. **(v0.4.0) A module with ports but no logic shows "Open a Verilog file".** With a valid file that has only a port list (`input [2:0] a, b; output [2:0] out_or_bitwise; output out_or_logical; output [5:0] out_not;` and no assigns), the badge says "RTL view, synthesized" but the panel shows the no-file empty state "Open a Verilog file (.v or .sv) to see its schematic." Expected: the module box with inputs on the left and outputs on the right, each undriven output marked with a short hint ("not driven yet"). The empty-file message must only appear when no Verilog file is active. This is also a badge/drawing disagreement (same class as bug 2).
22. **(v0.4.0) Error message picks the less helpful problem.** With a complete port list, then a line containing only `assign`, and `endmodule` deleted, the banner says "7458.v:8:7 missing endmodule". The nearest and more useful problem is the unfinished statement. Report errors in source order and explain the first one in beginner terms, for example "assign is incomplete: write assign name = expression;", then list the missing endmodule as a second item.
23. **(v0.4.0) Valid ports drawn ghosted.** In the same case, every port is drawn dashed (ghosted) even though the port list is complete and parsed without errors; the error is after the header. Ghost only ports that were actually recovered from broken code. Ports from a cleanly parsed header stay solid.

## Known issues (from NOTES.md)

5. Logical operators (`||`, `&&`, `!`) look the same as bitwise ones (`|`, `&`, `~`).
6. Structural boxes are not overlaid on a stale synthesized diagram.
7. Replicated groups like `{5{a,b,c,d,e}}` expand to one wire per bit.
8. Bus width labels can touch the port chevron on very short wire segments.

## Feature ideas (v0.5, not bugs)

- Learning mode: live syntax guide and preview diagram. While a line is incomplete, show the template of the construct being typed above the diagram (for example "assign <name> = <expression> ;") with the current part highlighted and what is still missing. In the background, auto-complete the missing tokens (";", ")", "endmodule") and draw the result dashed and labelled "preview", with "?" pins for operands not typed yet (for example "a |" draws an OR gate with inputs a and ?). Needs a Hints on/off toggle so it can be turned off for recall practice. Deterministic (parser based), no network.
